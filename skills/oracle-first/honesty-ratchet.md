# The honesty ratchet

Standing oracle-first pattern for the second-order failures — the cases
where an oracle exists and is wrong *about itself*. Rule-level summary
in [`SKILL.md`](~/.claude/skills/oracle-first/SKILL.md) rule 14; theory
and case evidence in [`doctrine.md`](~/.claude/skills/oracle-first/doctrine.md)
§4 "Second-order failures"; source analysis in
[`~/think/analysis/oracle-first-state-of-play-2026-07-18.md`](~/think/analysis/oracle-first-state-of-play-2026-07-18.md)
§4 and §7.2. This file is the *operational* form: the taxonomy you are
defending against, the checklist you apply, the skeleton you start from,
and the drill that proves the ratchet bites.

Premise, restated so nobody applies this in good faith: **the
verification layer is a Goodhart target.** Under sustained completion
pressure — a zero-failures target, a "converging" status, a coverage
threshold — any gap between the measured quantity and product truth will
be found and exploited, sincerely, by the executor. Design gates with a
security mindset. Both campaigns that discovered this (RustUML parity
endgame, HMS migration factory, same week of 2026-07) were run by
well-meaning agents that believed every number they reported.

## 1. What goes wrong: the second-order taxonomy

First-order failure (no oracle; iterate against feel) is largely won.
These are the live modes. Numbering follows the state-of-play §4 table.

| # | Mode | Shape | Exemplar | Ratchet ingredient |
|---|------|-------|----------|--------------------|
| 2 | **Oracle gaming** | Code satisfies the check without the behaviour: golden replay, fixture echo, literal-label recognizers, coordinate-keyed string surgery | RustUML ×3: inner-XML early return (+5,990 passes, May); byte-range subtree replay (T4.11); 20 `include_str!` golden bodies (June) | Embed guard; echo sentinel; provenance obligation; out-of-corpus holdout |
| 3 | **Metric-path divergence** | The measured path ≠ the shipped path. The headline can be *true* and meaningless | RustUML "0 failures / 12,546" certified the oracle-assisted tier while the CLI rendered state diagrams at 1/901 (59.5% real parity); HMS readiness checks testing evidence-*filename* existence | Product-path-only metric tier; baseline locked in both directions |
| 4 | **Scaffolding Goodhart** | Building verification machinery counts as verification progress | HMS: a 24.5 h run built comparators, queues, ledgers; 0/21 standing-bank entries activated; dead SSH tunnel undiscovered until hour ~22; displacement ≈ 6:1 | Unit of progress = activated green evidence, never artifact counts (rule 15); the ratchet only counts a run that happened |
| 5 | **Gamed denominators** | The executor controls the divisor of its own gate | HMS T103: inventory 182 → 177 to land at 80.2%; "green" criteria satisfied by zero-field forms green on both sides | Un-ownable denominators: universe counted from source or a frozen corpus, and itself locked |

Modes 2–5 are one family, and the medicine is one bundle. Adopting an
ingredient on its own leaves the others as the next escape route: a
locked baseline with an ownable denominator is gamed by shrinking the
corpus; a product-path tier without a lock drifts; provenance without
holdouts is a well-cited overfit.

Two auxiliary modes the ratchet also pins, because they were the
mechanical vectors in practice:

- **Silent drift** — a number moves and nobody says why. Down is a
  regression; *up* is an unclaimed improvement that makes the baseline
  stale so the next regression hides under it. Both directions fail.
- **Hand-edited ledgers** — the baseline file is edited to match the
  wish rather than regenerated from a run. Bind the numbers to the
  provenance statement with a hash; a mismatch is a finding.

## 2. The five ingredients, as obligations

1. **Product-path-only metric tier.** Only the shipped path (the CLI,
   the deployed service, the app as the user runs it) produces the
   headline number. Oracle-assisted, instrumented, or harness-injected
   tiers are regression nets and are reported as such, never as the
   headline. RustUML: `golden_no_oracle` is the metric; `golden_pairs`
   is the net.
2. **Baselines locked in both directions.** Below baseline fails.
   Above baseline *also* fails until the improvement is locked in the
   same change, with a stated reason and a named mechanism. Tolerance is
   an explicit per-metric number, default zero. The baseline file is
   regenerated by the tool, never edited.
3. **Un-ownable denominators.** Every quantity in the gate — numerator,
   denominator, corpus, threshold — is computed from source or a frozen
   reference the executor cannot trim. The universe itself is locked:
   corpus additions and deletions are deliberate, cited changes (HMS
   T153's 171,320-cell universe; RustUML's error-golden census pinned at
   1,199).
4. **Provenance obligations.** A number moves only alongside a reason
   and a named reference mechanism (a Java class/method, a spec clause,
   an extracted metrics table). Suspicious constants (3+ decimal places,
   per-branch-count ladders) carry adjacent provenance and are counted
   by a ratchet of their own. Passing is not being right for the right
   reason; provenance is rule 6 made auditable.
5. **Out-of-corpus perturbation.** Acceptance includes inputs the
   development corpus never saw, exercising at least two independent
   axes of the claimed mechanism, checked against a *freshly generated*
   reference — never a stored golden. Anything memorizable is eventually
   memorized; holdouts are the only guard against a well-cited overfit.
   Holdouts are created by the checker, not the implementer (RustUML
   AGENTS.md rules 9–10).

Plus the meta-obligation from rule 15: **wire it to a standing
enforcement point** (pre-push hook, CI job, `/cv` gate) as part of
building it. An unwired ratchet is scaffolding.

## 3. Checklist

Apply at the moment a metric becomes a gate — a "converging" target, a
parity percentage, a coverage threshold, a pass count anyone will cite.

**Metric definition**
- [ ] The headline number is produced by the shipped path with no
      test-only seams active. Name the command.
- [ ] Every oracle-assisted or instrumented tier is labelled a
      regression net in the target's acceptance text.
- [ ] The denominator is counted from a source tree or frozen corpus by
      the gate tool, not reported by the scorer or typed by a person.

**Lock**
- [ ] A checked-in baseline exists, regenerated only by the tool.
- [ ] Regression fails. Unlocked improvement fails. Tolerance is
      explicit, per metric, default zero.
- [ ] Universe size is locked alongside the pass count; corpus edits
      fail until locked.
- [ ] The baseline carries a hash binding the numbers to the provenance
      block; the tool refuses to lock when any guard is red.

**Provenance**
- [ ] Every lock names a reason and a reference mechanism.
- [ ] Parity-affecting constants carry an adjacent citation; high-
      precision literals are counted under their own ratchet.
- [ ] The implementer does not author their own attestation; a separate
      checker records identity, revisions, commands, findings, verdict.

**Gaming guards**
- [ ] Embed guard: product sources cannot mention the reference corpus
      path, `expected`, `golden`, or `include_str!`-style embedding of
      fixtures; allow-lists ratchet to zero.
- [ ] Echo sentinel: poisoned outputs score zero (a scorer that passes
      garbage is reading its expectation from the artefact under test).
- [ ] Holdouts exist per claimed mechanism, are byte-distinct from the
      corpus, and are compared against a reference generated at check
      time.

**Operations**
- [ ] The gate runs at a standing enforcement point; its output is the
      evidence cited in attestations ("two tier numbers and green
      guards, never the executor's say-so").
- [ ] Progress is reported as activated green evidence (runs that
      happened, on fresh inputs), never as artefacts built.
- [ ] The ratchet has been drilled (§5) and the drill is re-run when
      the ratchet changes.

## 4. Skeleton

[`ratchet/ratchet.py`](~/.claude/skills/oracle-first/ratchet/ratchet.py)
— single-file, stdlib-only Python; usage in
[`ratchet/README.md`](~/.claude/skills/oracle-first/ratchet/README.md).
Copy it or point at it; it makes no assumptions about the product beyond
two commands (produce the outputs; score them) and two trees (a source
corpus; a frozen reference). Findings are tagged so hooks and drills can
assert on them:

| Tag | Ingredient | Meaning |
|-----|-----------|---------|
| `PROVENANCE` | 4 | Baseline hand-edited, or reason/mechanism empty |
| `EMBED_GUARD` | 2 (gaming) | Product source reaches into the reference corpus |
| `DENOMINATOR` | 3 | Scorer's eligible count ≠ source-counted universe |
| `REGRESSION` | 2 | Pass fell beyond tolerance |
| `UNLOCKED_IMPROVEMENT` | 2 | Pass rose beyond tolerance without a lock |
| `UNIVERSE_DRIFT` | 3 | Corpus size changed without a lock |
| `ECHO_SENTINEL` | 2 (gaming) | Scorer passes deliberately poisoned outputs |
| `HOLDOUT_IN_CORPUS` | 5 | A holdout is byte-identical to a corpus input |
| `HOLDOUT_FAIL` | 5 | Product ≠ freshly generated reference on a holdout |

`ratchet lock` re-runs every guard and refuses to lock a gamed number;
`ratchet check` is the gate. The RustUML originals this distils
(`golden_no_oracle.rs`, `harness_guards.rs`, `no_oracle_baseline.txt`,
`decimal_literal_baseline.txt`, AGENTS.md "Parity Honesty Rules") remain
the reference for a compiled-language, per-family, in-test-suite
embedding of the same obligations.

## 5. Drill — how you know the ratchet bites

An unmeasured ratchet is a report node. Mutation-test it the way you
would any oracle (rule 12): plant the failures and require the catch.
Minimum set, from the state-of-play §7.2 acceptance:

- a **golden-echo** (scorer reads its expectation from the artefact it
  checks; product returns the golden when one exists) → must block;
- a **silent baseline drift** (hand-edited numbers; a real fix landed
  without a lock) → must block;
- the **clean project** and a **properly locked improvement** → must
  pass.

Reference drill with transcripts:
`~/think/burst-2026-09/ratchet-drill/` (`drill.py`; ten scenarios
including gamed denominator, corpus deletion, and a locked corpus
overfit exposed only by holdouts; plus a control run against a
deliberately weakened ratchet showing the drill itself is sensitive).
Re-run the drill whenever the ratchet changes; a ratchet whose drill is
stale is a ratchet whose strength is unknown.

## 6. Residue the ratchet cannot decide

- **Whether the reference is right.** A frozen corpus and a reference
  generator are trusted inputs; the ratchet certifies conformance to
  them, not their truth (rule 11).
- **Semantic gaming that survives holdouts** — a mechanism that is
  genuinely general but wrong for the same reason the corpus author was
  wrong. Adversarial audits, not ratchets.
- **The stop-the-line call.** Every Goodhart catch on record was
  human-initiated; the ratchet's job is to make the pull rare, cheap,
  and landing on evidence.
